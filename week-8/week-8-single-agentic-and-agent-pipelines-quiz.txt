## 1. Explain the concept of a stateful directed graph in agent pipelines. How does it differ from a simple linear pipeline?

A stateful directed graph is a workflow structure in which each step, represented as a node, can retain and use information generated during previous steps. The graph is connected through edges that define how the workflow progresses, allowing branching, looping, and conditional execution based on the current state. In contrast, a simple linear pipeline follows a fixed sequence of operations from beginning to end without retaining state or dynamically changing its execution path.

---

## 2. Describe the role of nodes and edges in an agent workflow. Give an example of each.

In an agent workflow, nodes represent the individual operations or tasks performed by the system, such as processing user input, calling an external tool, or generating a response. Edges define the connections between these nodes and determine how information flows through the workflow. For example, a Calculator Tool can be represented as a node, while the connection that routes a mathematical query from the intent analysis stage to the calculator is an example of an edge.

---

## 3. What is conditional routing in an agent system? Design a simple rule-based routing logic for three different query types.

Conditional routing is the process of directing a user's request to the most appropriate tool or action based on its intent. It enables an agent to make decisions rather than following a fixed sequence of operations. For example, if a query contains words such as "calculate" or "compute," it can be routed to a Calculator Tool. Queries requesting keyword extraction can be sent to a Keyword Extraction Tool, while requests to count words can be routed to a Word Counter Tool. Any unsupported queries can be handled by a default response module.

---

## 4. Why are cycles (loops) important in agent pipelines? Provide a use case where a retry loop is necessary.

Cycles, or loops, allow an agent to repeat an operation until a desired outcome is achieved or a stopping condition is met. They are particularly useful when tasks may fail temporarily or require multiple attempts to succeed. For example, if an external API request fails because of a network timeout, the agent can retry the request several times before reporting an error. This improves the overall reliability and robustness of the system.

---

## 5. Explain how a single-agent system can simulate multi-agent behavior internally.

A single-agent system can simulate multi-agent behavior by dividing its workflow into multiple logical roles executed within the same program. For instance, it may first analyze the user's request, then determine which tool should be used, and finally generate or format the response. Although these roles resemble separate agents, they are coordinated by a single system, reducing implementation complexity while still providing modular and flexible behavior.

## 6. What are JSON schema tools? How do they help in structuring tool inputs and outputs?

JSON schema tools define a standardized structure for the data exchanged between agents and external tools. They specify the expected fields, data types, and validation rules for both inputs and outputs. This ensures that data is formatted correctly before processing, reduces the likelihood of errors, and allows different components of an agent system to communicate consistently and reliably.

---

## 7. Compare sequential tool calls and parallel tool calls. When would you prefer one over the other?

Sequential tool calls are executed one after another, with each step depending on the output of the previous one. They are appropriate when tasks have dependencies and must follow a specific order. In contrast, parallel tool calls execute multiple independent tasks simultaneously, reducing overall execution time. Parallel execution is preferred when the tasks do not rely on one another and can safely run concurrently.

---

## 8. How would you implement error handling in a tool-using agent? Provide at least two strategies.

Error handling helps ensure that an agent continues to operate reliably even when unexpected issues occur. One common approach is to use try-except blocks to catch exceptions and return meaningful error messages instead of terminating the workflow. Another strategy is to implement retry mechanisms that automatically repeat failed operations, such as API calls, after a short delay. Logging errors for debugging and monitoring is also a useful practice for maintaining and improving the system.

---

## 9. What is trajectory evaluation in agent systems? Why is it important beyond just checking final output?

Trajectory evaluation examines the complete sequence of actions an agent takes while solving a task rather than focusing only on the final output. It considers intermediate decisions, tool selections, and execution steps to determine whether the agent followed an effective reasoning process. This makes it easier to identify errors, improve workflow design, and optimize agent performance, even when the final answer appears correct.

---

## 10. Define task completion rate and cost metrics. How would you measure and optimize them in a real-world system?

Task completion rate measures the percentage of user tasks that an agent successfully completes, while cost metrics measure the computational or financial resources consumed during execution, such as API calls, processing time, or infrastructure costs. These metrics can be tracked across many interactions to evaluate overall system performance. They can be optimized by improving routing accuracy, minimizing unnecessary tool calls, selecting efficient algorithms, and balancing resource usage with successful task completion.
